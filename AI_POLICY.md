# AI Usage Policy

The following policy reflect the repo owner's stance on AI usage, and outlines strict guidelines for its use within this repository.

## Guidelines

- Any PR presentation, issue, comment, review, or more generally any human-to-human communication blatantly generated by AI will be ignored or rejected, and the author possibly blocked, even if, for example, the PR code itself is human-written, or comment 1 from user x is human-written and comment 2 from same user is AI-generated.
- Any code or documentation generated by AI should be thoroughly reviewed by a human before submitting a PR. Disclosing it's usage is not mandatory.
- PR's adressing an issue with the `Good first issue` label may not use AI for it, since those are intended either for experimented developers to get familiar with the codebase, or for coding beginners to generally learn to code and to contribute to open source software.
- Note that the usage of `greptile` and `github copilot` for PR reviews is not contradictory, since their status is **explicit**. As such, others can directly know how to perceive the value in their claims.

That's it. If you want to know _why_ those guidelines exist, see the section below.

## Motivation

The stance of a given person on AI for software dev can be summarized by his answers on a few questions.

### Do you use AI for ...?

- A) code generation?
- B) documentation generation (in-code, markdowns...)?
- C) code reviews(local agent, greptile, github copilot)?
- D) communication (PR and issues comments)?

Each question can be answered with one of the following options:

1. Never
2. Sometimes, with full human review.
3. Sometimes, with partial or no human review.
4. Always, with full human review.
5. Always, with partial or no human review.

### Answers

`pyochain` answers are, as of 2026-10-05:

- A) code generation? **2**
- B) documentation generation? **2**
- C) code reviews? **2**
- D) communication? **1**

### Explanation

Adressing `D` first, if I want to talk to an AI, I know which site to use.

It just comes out as simply disrepectful to forward the time someone spend expressing his toughts to an AI, asking it to generate a response.

On the other points, right now, advanced models can be tasked with writing new features, fixing bugs, refactoring an architecture, or adding tests, with working results almost everytime.

As such, generating code with it is perfectly fine, as long as reviews are exhaustive.

#### Why review?

New features code is often unecessary verbose, poorly in-line with pre-existing conventions, and difficult to read and maintain.

Agents will also go to any route to fix a given bug, even if that induces severe performance regressions or unecessary complexity. They will also often introduce out-of-scope cosmetic changes.

For testing, AI-generated code is just a big no.

Cheating results, partial coverage and unecessary assertions are almost always present. Worst of all, the moment tests are involved, all abstractions considerations seem to fly out of the window, with some of the worst code repetition happening there.

Architectural refactoring is impossible for them ATM.

Worst of all, it can often _seem_ like the goal was completed, and on further inspection, the underlying issues remain unresolved. For example, moving methods into free functions, renaming classes/traits, shuffling modules and their members around, in other words, purely cosmetic changes without adressing the original goal.

Even without cosmetic changes, trading performance and readability to achieve architectural improvements is another common "solution".

Reviews are more of a mixed bag. They can catch non-obvious issues, but will also often incorrectly flag things, leading to false positives and thus wasted time.

Finally, documentation prose style is almost always very discutable, with annoying analogies and comparaisons such as "it's this, not that", unecessary technical jargon, etc...

The actual content, altough correct most of the time, is either hard to maintain with lots of enumerations related to implementation details, filled with unnecessary content, many repetitions, or all of that combined.
